# Configuración de membresías recurrentes

El módulo usa Stripe Checkout en modo `subscription`, Stripe Billing y el portal del cliente. La API HTTP se fija en `2024-06-20`; el endpoint de webhooks del propietario debe usar también esa versión. Solo se admiten precios fijos recurrentes MXN, cantidad uno, sin prueba gratuita, cupones, impuestos añadidos ni prorrateos. El importe configurado es el total final con IVA.

En `config.php` se configura `membresias.habilitadas` y un mapa `membresias.planes`. Cada plan contiene `nombre`, `stripe_price` (`price_…`), `importe_centavos` entero, `moneda` (`mxn`), `intervalo` (`month` o `year`) y `productos` (IDs locales con políticas y videos válidos). Sin configuración válida no se ofrecen nuevas suscripciones. Las suscripciones ya contratadas conservan una copia del precio y los contenidos de su contrato, aunque se modifique la configuración posterior.

Aplicar `sql/004_io_membresias.sql` después de 001–003. Publicar la página `/io/tienda/membresias.php`. Los botones de suscripción exigen sesión y CSRF; los enlaces de Checkout y portal se obtienen desde el servidor. El cliente de Stripe no se busca por correo: se vincula a una fila local con un token aleatorio y metadata de la suscripción.

Suscribir el webhook firmado a `checkout.session.completed`, `invoice.paid`, `invoice.payment_failed`, `customer.subscription.updated` y `customer.subscription.deleted`, además de los eventos de pagos individuales. `checkout.session.completed` vincula la cuenta, pero no concede contenidos. `invoice.paid` comprueba ID de suscripción, cliente, estado pagado, moneda, importe, cantidad, Price ID y período de una sola línea recurrente. Facturas con ajustes, descuentos o prorrateos se rechazan para revisión; no se otorgan accesos con montos inesperados.

Una factura pagada se registra una sola vez. La renovación amplía el acceso hasta el final del período facturado; eventos antiguos no acortan una renovación ya pagada. Los rechazos conservan únicamente el tiempo previamente pagado. La cancelación solicitada desde la página se programa al final del período. Cuando Stripe informa una terminación efectiva, se limita la vigencia y se cierran sesiones expiradas. Una factura atrasada no reactiva una suscripción ya cancelada. Las reglas de visualización única de los contenidos incluidos se conservan al renovar: renovar la membresía no reinicia una visualización consumida.

Configurar el portal de Stripe para permitir método de pago y cancelación al final del período. Desactivar cambios de plan, descuentos y prorrateos en el portal: no forman parte de este contrato de precio fijo. Para cambiar plan, cancelar el anterior y contratar el nuevo después de revisar el período pagado. Cada plan solo permite una suscripción pendiente o vigente por cliente.

Para aceptar la integración con la cuenta del propietario: crear un Price mensual y otro anual de prueba, configurar los IDs, contratar, comprobar ausencia de accesos antes de `invoice.paid`, renovar usando Stripe Test Clocks, rechazar un pago, actualizar tarjeta, cancelar al final y comprobar vencimiento. Reenviar eventos y verificar que no se duplican accesos. La suite local utiliza un transporte simulado y una base temporal independiente; no acredita pruebas contra una cuenta de Stripe ni hace cargos reales.

Un checkout pendiente se reutiliza consultando su sesión remota. Al vencer su fecha local, solo se libera la reserva si Stripe confirma el estado `expired`; una sesión ya completada espera su webhook y no genera otra contratación. Si una creación terminó en timeout sin guardar referencia, se permite reintentar con la misma clave durante 23 horas. Después se bloquean nuevas creaciones hasta que el técnico concilie la suscripción en Stripe, evitando reutilizar una clave cuya garantía de idempotencia podría haber vencido.
